## 1. タスクの状態列挙（MVP 案）と GTD 対応


| 内部値 `status`  | 画面表示（例） | GTD 上の位置づけ                                 | 備考                          |
| ------------- | ------- | ------------------------------------------ | --------------------------- |
| `inbox`       | Inbox   | **受信箱**（未整理）                               | 新規即メモの既定。Inbox プロジェクト上のタスク  |
| `next`        | 次の行動    | **Next**（次にやる行動）                           | プロジェクト文脈で実行可能にした行動          |
| `in_progress` | 進行中     | 実際に手を付けている 1 本（多く同時 1 本推奨は UX 上の目安。禁止はしない） |                             |
| `waiting`     | 待ち      | **待ち**（人・外部起因）                             |                             |
| `done`        | 完了      | 完了。一覧からは**デフォルト非表示**やフィルタで扱いやすくする          | 論理削除の代替としても可（Could）         |
| `someday`     | いつか     | **いつか** / Someday / Maybe                  | Should。MVP に含めないなら v0.3 で追加 |


- **遷移**: 原則どの `status` からどの `status` も許可（Inbox から `next` への「整理」が主導線）。  
- タスク移動（別プロジェクトへ）に伴い、`inbox` から `next` へ**自動**でよい、などのルールは実装でメッセージ表示まで含めて定義可。

`status` の DB 表現は **TEXT** または **ENUM** 型。マイグレーション方針は [ARCHITECTURE.md](./ARCHITECTURE.md) に従う。

## 3. API 下書き（MVP 案）

- **形態**: **JSON over HTTP**、**REST 風**（リソース名＋HTTP メソッド）。**Route Handler**（例: Next.js `app/api/.../route.ts`）に集約。  
- **認証**: 全 API はセッション（Cookie）＋**ログイン必須**。未認証は `401`。  
- **慣習**  
  - 一覧: `GET`、作成: `POST`、1 件: `GET/PATCH/DELETE`  
  - ID は path（例: `/api/programs/{id}`）

**エンドポイント案（v0.2）**


| メソッド     | パス                                 | 説明                                          |
| -------- | ---------------------------------- | ------------------------------------------- |
| `GET`    | `/api/programs`                    | 自分のプログラム一覧                                  |
| `POST`   | `/api/programs`                    | 作成                                          |
| `GET`    | `/api/programs/{id}`               | 詳細＋子プロジェクト含めても可                             |
| `PATCH`  | `/api/programs/{id}`               | 更新                                          |
| `DELETE` | `/api/programs/{id}`               | 削除（子に依存があれば 409 等）                          |
| `GET`    | `/api/projects`                    | クエリ: `?programId=` など                       |
| `POST`   | `/api/projects`                    | 作成（Inbox 専用は `isInbox` 等）                   |
| `GET`    | `/api/projects/{id}`               | 詳細                                          |
| `PATCH`  | `/api/projects/{id}`               | 更新                                          |
| `DELETE` | `/api/projects/{id}`               | 削除                                          |
| `GET`    | `/api/tasks`                       | フィルタ: `projectId`, `status`, `dueBefore`, 等 |
| `POST`   | `/api/tasks`                       | 作成。既定: Inbox プロジェクト＋`inbox`                 |
| `GET`    | `/api/tasks/{id}`                  | 詳細                                          |
| `PATCH`  | `/api/tasks/{id}`                  | 更新（**projectId 変更＝再配置**可）                   |
| `DELETE` | `/api/tasks/{id}`                  | 削除                                          |
| `GET`    | `/api/me` または `GET` `/api/summary` | ダッシュボード用集計（任意。フロント集計で代替可）                   |
| `GET`    | `/api/workload`                    | 週 6 区間の〆切件数＋週内タスク ID 一覧等（集計専用）              |
| `PATCH`  | `/api/preferences` または `PUT`       | テーマ等（MVP: localStorage のみなら省く）              |


**tRPC/Server Actions への置換**は技術選定で許容。本書の「リソースと操作の分割」に沿う限り、RPC 名を対応付けてよい。

## 4. 初回登録（Google 初回コールバック）時の Inbox 自動生成

**トリガー**: **初めて**当該 `User` 行が作られた直後（OAuth 初回のサインアップ 1 回限り）。既存ユーザー再ログインでは**実行しない**。

**手順（原子性: 1 トランザクション推奨）**  

1. `Program` を 1 件作成: 名前候補 `受信箱` または `Inbox`（i18n 可）。`startOn` / `endOn` は**広い期間**（例: 当日〜2099-12-31）または**NULL 許可**の場合は NULL（スキーマで定義）。
2. その配下に `Project` を 1 件: 名前同様。`isInbox = true`（または専用 `type = 'inbox'`）を**必須**で付与。`userId` があるスキーマでは**一意制約**に利用（[ARCHITECTURE.md](./ARCHITECTURE.md)）。
3. 以後、即メモはこの `Project.id` を **API が既定で使用**（クライアントはプログラム/プロジェクトを送らない）。

**制約**  

- ユーザーあたり **Inbox 用 Project は 1 つ**（重複生成を防ぐユニーク制約 or アプリ層検査）。  
- 手動で Inbox プログラム/プロジェクトを**削除**しようとした場合は **MVP: 不可** または **確認＋全タスク再配置**（Should 以降で定義）。初期は**削除不可**でよい。
