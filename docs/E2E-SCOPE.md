## 1. 方針

- **本番**ではなく、**予測可能な環境**（`localhost` ＋ テスト用 DB または**モック**）で回す。  
- **Google 本番アカウント**を CI で使わない。`PLAYWRIGHT_GOOGLE` のような**専用テストユーザー**、または **E2E 専用の「バイパス」ログイン**（開発環境のみ有効＋`E2E_SECRET` 等）を導入するか、**手動**スモークのラインに倒す。  
- **MVP 必須**の 4 本は、どちらかが成立すれば可: ① 安定した**モック auth** ＋ ② **実 OAuth** 手動用チェックリスト。

---

## 2. 自動化するシナリオ（MVP 最小 A〜F）


| 優先    | シナリオ                                            | 成功条件（要約）                                                                               |
| ----- | ----------------------------------------------- | -------------------------------------------------------------------------------------- |
| A     | ログイン後、**ダッシュボード**（または Inbox へ**遷移**するホーム）が表示される | 未ログインにリダイレクトされない、主要見出しが表示                                                              |
| B     | **Inbox にタスク追加**                                | 1 行メモ or API 経由で、Inbox 一覧に表示                                                           |
| C     | タスクを**別プロジェクトに移動**（API）                         | `PATCH /api/tasks/:id` で `projectId` 変更後、`GET /api/tasks?projectId=...` の一覧に当該タスクが含まれる |
| D     | タスクを**完了**（`status=done` 等）                     | 一覧上で完了扱い（非表示 or ストローク等）                                                                |
| E（任意） | **負荷ビュー**に遷移し、週ブロックが**0 件**でも破綻しない              | 空状態メッセージ or 0 本                                                                        |
| F     | Inbox から **UI で別プロジェクトへ移動**                     | Inbox 一覧の行で移動先を選び実行後、当該タスクが Inbox から消える（`inbox-move-target` / `inbox-move-submit`）     |


**C と F の分担:** C は REST だけで移動後の**移動先プロジェクト側のデータ**を検証する。F は Inbox 画面の**フォームとサーバーアクション**の回帰で、「Inbox から消える」ことをブラウザで確認する。

---

## 3. 明示的に E2E の外（MVP）

- 本番 **Google 認証**の完全自動（CAPTCHA/2FA/セッション凍結のため）  
- パフォーマンス負荷・セキュリティスキャン（別ツール）

---

## 4. 次のアクション（実装済みの整理）

- **テスト専用ログイン:** 開発時のみ `E2E_AUTH_ENABLED=1` と `E2E_AUTH_SECRET` を有効にし、Credentials プロバイダで E2E ユーザーを確保する（詳細はリポジトリの `README.md`）。
- **CI:** まず `npm run lint` と `npm run build` から入れるのが無難。E2E は `DATABASE_URL`・`AUTH_SECRET` 等が要るため、シークレット設計が固まってから別ジョブで回す。
